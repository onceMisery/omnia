## 1. 结论摘要

本次评审以冻结基线 VCPToolBox `a8560b0ae4e7b1a7803a88093a9ebee391e21a7c` 与 VCPChat `c3e4855efa2b24c0578d76e17fd6c5f21857a539` 为准，逐项核对文档中的资产清点、源码引用和协议契约。

整体判断：文档的事实密度和可追溯性较高，基线 commit、绝大多数资产数量、关键契约行号、SQLite DDL 与运行限额均可复核；未发现方向性架构错误。主要问题集中在三处：

1. **LoomController 采信了上游 README 的旧命令表**，只登记 14 条命令，冻结 manifest 实际有 36 条。
2. **ScriptoriumCollaborator 采信了上游 README 的旧版本号**，文档写 manifest v3.3 / 17 命令，冻结 manifest 实际为 3.4.0 / 33 命令。
3. **M2 的标签提取与共现矩阵仍是旧 JS 文档口径**，标注的 `KnowledgeBaseManager.js` 行号已不再对应实际代码，且与同一文档 §4.3“Tag 为尾行”自相矛盾。

另有若干契约边界和文档精度问题，见 §4。

## 2. 方法与证据边界

- 基线核对：两仓 `git rev-parse HEAD` 与文档冻结 commit 一致，工作区无未提交改动；引用读取使用 `git show` 语义，不以工作区替代冻结树。
- 资产清点：`git ls-tree` 口径的目录/文件计数，配合 manifest 解析统计类型与协议值域。
- 契约核对：抽样读取文档标注的文件与行号，逐项比对函数、模板、常量与错误文本。
- 证据层级：本次为**静态阅读 + 资产清点**，未做运行录制、四象限 e2e 或真实 AppData 往返；不能据此签署产品兼容。证据层级定义见[架构设计 §11.1](Omnia-架构设计.md#L463-L474)。

## 4. 问题清单

### R-01 LoomController 命令集不完整（高）

**现状**：[M5 PRD](Omnia-M5深水区功能与分发-PRD.md#L24) 写“Loom 全部 14 命令”，[§6.1](Omnia-M5深水区功能与分发-PRD.md#L144) 标题为“命令全表”，[架构 §9](Omnia-架构设计.md#L430) 与[矩阵 BP-05](Omnia-复刻范围与对应矩阵.md#L219) 也以 14 命令为验收口径。

**基线证据**：冻结 [LoomController 清单](file:///D:/code/github/VCPChat/VCPDistributedServer/Plugin/LoomController/plugin-manifest.json) 为 **1.11.0，36 个 `invocationCommands`**。而上游 `LoomController/README.md` 最新 changelog 只到 1.9.0，M5 的 14 命令表正是旧 README 的应用/Skill 管理子集。

**缺失的 22 条命令**：`OpenVCPChatBrowser`、`list_tabs`、`switch_tab`、`close_tab`、`open_url`、`RequestBrowserAssistance`、`NavigateBack`、`NavigateForward`、`NavigateHome`、`ReloadPage`、`GetPageInfo`、`GetPageImage`、`click`、`type`、`send_keys`、`scroll`、`set_value`、`select_option`、`hover`、`check`、`wait_for`、`ExecuteAction`。

**影响**：BP-05 的对象就是“Loom 内置浏览器与网页自动化”，只实现/对拍 14 条命令无法覆盖原版的浏览器控制面；这些命令也是外部浏览器 + CDP 桥的实际入口，缺失会让 Loom 适配版停留在“应用/Skill 管理”，无法完成网页操作闭环。US-426 的“冻结树到能力清单完整”也会被卡住。

**建议**：

2. 若决定用 M3 的 ChromeBridge（42 条命令，名称有部分重叠）承接这 22 条，必须写明逐命令映射与行为对拍证据；ChromeBridge 是另一个插件/通道，不能默认等价。

### R-04 Manifest 值域容错不足（中）

**现状**：[插件系统设计 §3.5](Omnia-插件系统设计.md#L288-L293) 把 `entry_point` 定义为必填结构，`communication.protocol` 注明 `stdio|direct`。

**基线证据**：77 个启用 manifest 中：
- **17 个没有 `entryPoint.type`**，包括 RAGDiaryPlugin、LightMemo、ChromeBridge、VCPTavern、VCPLog、AgentAssistant、VCPTaskAssistant、VCPToolBridge 等；

**影响**：若 Rust 用严格 enum 或强制反序列化 `entryPoint.type`，会拒载 17/77 个插件，其中包含记忆双通道和审核链路的关键插件。`process_stdio` 与空值也没有定义行为。

**建议**：`EntryPoint` 的 `type`/`command`/`script` 全部 optional，但至少一个有效；`protocol` 按开放字符串处理，已知值 `stdio`/`direct`/`process_stdio`/缺失各定义行为；US-011 与 US-202 增加这 17 个 manifest 的加载 fixture。
