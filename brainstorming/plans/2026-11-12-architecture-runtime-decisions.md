# Omnia · 架构运行时设计决策记录

日期：2026-11-12。本文件是决策存档，不是现行规格；现行规格见 [架构设计](../../docs/Omnia-架构设计.md) v2.6。

## 背景

用户要求对照 VCPToolBox 与 VCPChat 分析并完善设计文档。对照冻结 commit（VCPToolBox `a8560b0ae4e7b1a7803a88093a9ebee391e21a7c`、VCPChat `c3e4855efa2b24c0578d76e17fd6c5f21857a539`）后发现架构设计缺少以下内容：

- 运行拓扑：原版管理面是独立进程（PORT+1）；VCPChat 主进程内嵌一个分布式节点，带 38 个节点侧插件目录。
- 启动顺序与停机生命周期。
- 取消传播：原版中断只取消上游请求，不终止在途工具；架构 v2.4 写的是“级联取消工具执行”。
- M3 各 crate 之间的依赖方向。
- 后端持久化目录与写入者、日志落点。
- 工具调用记录库的归属在架构、M0M1 PRD 与插件系统设计之间不一致。

架构 v2.5 补入基线事实，并提出十项设计建议，标注为待确认。

## 决策

| # | 条目 | 定案 |
| --- | --- | --- |
| 1 | M3 各 crate 的依赖方向 | omnia-ws 不依赖业务 crate；omnia-dist、omnia-approval、omnia-scheduler 依赖 omnia-plugin 与 omnia-ws；omnia-filefetch 依赖 omnia-dist；omnia-agent 自 M3 起依赖 omnia-ws |
| 2 | 审核留言追加的归属 | 留在 omnia-agent；omnia-approval 只产出留言文本 |
| 3 | 管理端口 PORT+1 | 不拆第二个进程，omnia-server 同时监听 PORT 与 PORT+1 |
| 4 | 桌面端内嵌分布式节点 | 节点端协议实现不依赖 omnia-server 与 omnia-agent，omnia-app 与独立节点进程都能装配 |
| 5 | 启动装配规则 | 构造参数取代构造后的互相注入；全部就绪后才监听；启动失败以非零退出码结束 |
| 6 | 停机生命周期 | 阶段次序、放行清单、拒绝响应与超时值按原版保留；增加插件子进程回收一步（DV-3） |
| 7 | 中断与在途工具 | 按原版，中断不终止在途工具；要终止须先登记新的 DV |
| 8 | 日志落点与脱敏 | 日志后端只在两个启动入口初始化；文件位置与轮转按原版对齐；脱敏在事件产生处完成 |
| 9 | 后端持久化目录 | 路径与环境变量按原版保留；每个路径只有一个写入模块 |
| 10 | 工具调用记录库 | 归 omnia-plugin，omnia-agent 经句柄使用 |
